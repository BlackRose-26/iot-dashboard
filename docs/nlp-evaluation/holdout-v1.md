# First-use holdout v1 — 20 November 2026

This is the preserved original first-use measurement. The later [language repair and consumed-set regression](../nlp-routing-repair.md) are separate; they do not replace this result or make this dataset unseen again.

The user required 100–300+ unseen cases, roughly 20–50 diverse examples per intent, kept separate from training and few-shot examples. This benchmark has **325 new synthetic cases: 25 for each of the 13 primary router intents**. The application, prompt, vocabulary, retrieval thresholds and runtime corpora were frozen before inference and were not repaired using its predictions.

English: 33/182 accepted. Taglish: 26/143 accepted. Among the 300 valid supported-intent cases, 34 matched their intended label/context. The high rejection rate is a serious conversational coverage gap, not evidence of successful understanding.

All 247 valid-request clarifications came from the scope/unknown-word guards. Across the entire set, the reasons included 94 `system_scope` and 167 `unrecognized_context` outcomes; some of those correctly reject unsupported cases. There were also mistakes after questions reached routing. No cases, labels or failure categories were removed to improve the score.

These results do **not** establish independent real-user accuracy. The set is developer-authored synthetic stress data, balanced by primary intent rather than sampled from event traffic. Gold labels have not received independent human adjudication. “Unseen” means new to this project's runtime examples and first model evaluation; absence from the foundation model's pretraining cannot be verified.

## Separation and diversity

- The inventory and frozen case file live under `backend/evaluation/`, outside the explicit runtime corpora. This whole directory is excluded from Graphify so test prompts cannot become project-retrieval examples.
- There are **182 English and 143 Taglish** cases, with at least **10 named utterance families per primary intent**. Cases include fragments, unfamiliar wording, typos, indirect requests, mixed greetings, negative instructions, source/time references, memory follow-ups and safety boundaries. They are individually authored rather than generated by swapping prefixes or dates over a small template.
- The pre-inference audit checked **911 seen references**: runtime corpora (including their older evaluation records), the earlier validation set, prior integration probes, NLP unit fixtures and prompt demonstrations.
- There were zero exact raw/usable-normalized collisions. There were zero near pairs under the preregistered rule: content-word Jaccard at least 0.70 **and** character-sequence similarity at least 0.84. The same check found no within-set near pairs. These are lexical checks, not proof that all semantic paraphrase overlap has been eliminated.
- Twenty-five per intent refers to the **13 primary intents**, not every knowledge/definition/social subtype. Subtype counts are in the manifest; many have only 2–5 cases, so strong subtype-level generalization claims would still be inappropriate.
- Neither the valid questions rejected by the vocabulary gate nor the difficult unfamiliar questions were filtered out before scoring. Evaluation inputs were never added to training, vocabulary aliases, reviewed examples or few-shot retrieval.

## Frozen protocol and scoring

`backend/holdout_audit.py` records dataset, runtime-source, prompt, runtime-corpus and evaluator hashes in `backend/evaluation/holdout-v1.manifest.json`. The dataset SHA-256 is `692b28787ae9a109bf98dd7cbda1bbc2b5027493b0027f556c17cb05914525f6`. Verification succeeded before and after the run. The local model's actual digest is recorded with the results.

`backend/evaluate_holdout.py` called the real core `Assistant.ask` service against disposable XAMPP data. It exercised local conversation matching, vocabulary/privacy guards, ordinary train-only retrieval, local Ollama, backend semantic resolution and returned contexts. Private memory and owner-reviewed examples were disabled. Synthetic test staff prevented the rate limiter from becoming a confound. Real application records were not read or changed.

The evaluator observes returned labels without changing inference. Exact labels, primary labels and accepted semantic outcomes are reported separately. Before inference, three help questions allowed either the social-help route or the reviewed assistant-capabilities card. Knowledge follow-ups could use their inherited knowledge label if all preregistered continuity fields matched. These equivalences did not increase the final accepted count above the exact-label count. Provider errors, refusals and valid-request clarifications remained in the denominator.

The measurement concerns intent/subtype selection and the annotated follow-up context. It does not fully score factual prose, every analytical filter or every displayed number. It also does not evaluate browser/authentication behavior or physical hardware.

The runner wrote a consumption ledger before the first test request and refuses a second silent “unseen” run. This set is now **consumed**: any later reuse is a regression test. Do not tune vocabulary/prompts/few-shot examples on these questions and continue to describe the resulting score as held-out performance.

## Evidence and next work

- [Measured case-level results](results/holdout-v1.json): case IDs, predicted/expected labels, failures, timings and confidence summaries; no answer text or private records.
- [Frozen manifest](../../backend/evaluation/holdout-v1.manifest.json) and consumption ledger bind the run to the predictor and scorer versions.
- [Per-intent figure](holdout-v1-intents.png) shows every category, including zero-score categories.
- Five benchmark-protocol tests passed: balance/diversity, overlap audit, immutable freeze/runtime drift, denominator/error accounting, and equivalent-label/context accounting. Runtime app files remained unchanged during this task.

The earlier 21-case regression and 24-case development-validation scores are historical development checks. Their high scores must not be presented as broad correctness evidence. This larger service-level holdout uses different cases and a broader processing path, so the percentages are not a controlled before/after model comparison.

The next improvement should address general vocabulary/subject discrimination, resilient English/Taglish understanding and correct dialogue continuation using **separate development material**. Preserve privacy and read-only controls. Review this benchmark's label ambiguity independently, and obtain a fresh externally authored/reviewed holdout before another generalization claim. Do not transplant its failed prompts into the runtime corpus.

Methodology follows [scikit-learn's evaluation separation guidance](https://scikit-learn.org/stable/modules/cross_validation.html), [classification metrics](https://scikit-learn.org/stable/modules/model_evaluation.html), and [Google's training/validation/test distinction](https://developers.google.com/machine-learning/crash-course/overfitting/dividing-datasets).
